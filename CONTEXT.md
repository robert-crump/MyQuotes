# MyQuotes — Domain Glossary

## Core domain objects

**Quote** — a single quotation with text, author, source, any number of Hashtags (`getTags()`: never null, normalized, deduplicated ignoring case, alphabetical), its **rejected tags** (`getRejectedTags()`, #55: tags the user said not to suggest for it, normalized the same way, never one of its own tags), favorite status, in-app view count and last-view time (`timesShown`/`lastShown`, bumped on every swipe in the main browse flow), `addedAt` (stamped by `QuoteCollection.add`, kept by `edit`; `0` for quotes that predate the field or were restored from a file without it), and a stable integer id.

**Quote Collection** — the canonical, ordered set of all quotes the user owns. Responsible for CRUD, id assignment, persistence, and notifying observers when the set changes. Implemented as a plain Java object (not a ViewModel) held by `MyApplication` for the lifetime of the process. The authoritative source of truth for quote data. Constructed over a Quote Store; owns bootstrap (`loadFromStore()`, called from `MyApplication.onCreate`, which also trims author/source and gives each tag one spelling across the collection — the first one found — and saves once if that changed anything or the Quote Store held an older format). `add` and `edit` give a quote's tags the spelling they already have elsewhere; `setList` (import, restore) unifies spellings like the load. Owns the mutation invariants: `edit` preserves favorite and view state (and the rejected tags, unless given new ones), `add` and `edit` drop rejected tags the quote has, `toggleFavorite` is the only favorite path, empty lists are persisted. Background workers do not use the Collection; they read the Quote Store.

**Quote Store** — the persistence seam under the Quote Collection (`QuoteStore`): load the quote list (empty when nothing stored), save the list (including an empty one), whether anything has ever been stored, and whether the stored data is in an older format (`isOldFormat`: a bare array or a `QuoteCodec` envelope below the current version). Adapters: `SharedPreferencesQuoteStore` (`QuotePrefs/quotes_json`) in production, `InMemoryQuoteStore` in test sources. `MyApplication` builds the store and exposes it via `getQuoteStore()`; `DailyQuoteWorker` and `BackupWorker` read it by name instead of going through the Collection.

**Hashtag** — a label on a Quote (#49, replacing the single free-text Category; see ADR-004). One token of Unicode letters, digits and `_`, stored without `#` and shown with it. The rules live in `Hashtag` (pure): `normalize` drops a leading `#` and every character a tag can't hold; tags compare ignoring case, and a tag that already exists anywhere in the collection keeps its spelling (typing `love` when `#Love` exists gives `Love`), so `#love` and `#Love` never coexist. An old category converts with `fromCategory`: invalid characters dropped, words joined in CamelCase (`"Life Wisdom"` → `LifeWisdom`); an empty category means no tags.

**Hashtag set** — the union of the tags on all quotes, sorted alphabetically. A tag exists only while a quote has it: there is no stored list and no Add action (the old `CategoryPrefs/saved_categories` key is removed on startup). Owned by `Hashtags` (held by `MyApplication`): `all()`, `quoteCounts()` (a quote counts once per tag), `quotesWithAny`, `canonical`, `mergeTarget`, `rename`, `delete` and a LiveData of the set. Rename and delete each go through one batched `QuoteCollection.replaceTag(old, newOrNull)` (compared ignoring case; one emission, one save); renaming to an existing tag merges, and a quote that had both keeps it once. Rejected tags follow: renamed, removed on delete, dropped where the quote now has the tag. Delete removes the tag, never the quotes. `HashtagsActivity` shows the set as a wrapping flow (`FlexboxLayoutManager`) of `#Tag` over `Nx`, sorted A-Z or by highest count (the app bar's sort button; equal counts alphabetical, `Hashtags.byCount`; remembered as `UiPrefs/hashtags_sort_by_count`), followed by a "No hashtag · Nx" entry (italic, never selected; opens `QuoteQuery.untagged()`; `Hashtags.untaggedCount()`, hidden at 0) and a "Has suggestions · Nx" entry (#55; same look; opens `QuoteQuery.suggested()`; the quotes with at least one suggestion, counted off the main thread whenever the collection emits; hidden at 0 and until counted). A tap on a tag opens its **hashtag sheet** (`HashtagSheet`, a `BottomSheetDialogFragment`, #51): Show N quotes (the tag filter search), "Suggested for N quotes" (#56; opens `QuoteQuery.suggestedFor(tag)`; counted off the main thread with `SuggestionRanking.countSuggestedFor`, shown once counted, hidden at 0), Rename, Delete (the screen's own dialogs, via `HashtagSheet.Host`), and a read-only Suggestions section from `HashtagSuggester.profile` (#52): "Not suggested yet: on 3 quotes, needs 5.", or "Words: gratitude (6/9), grateful (4/7)." with every reason word (or "No word is strong enough yet to serve as a predictor for this hashtag.") and, when an author qualifies, "Author: Rumi (4/5), Seneca (3/4).", when a source does, "Source: Masnavi (3/4).", and when another tag does, "With: #Grief (4/4), #Death (6/9).", then (for every tag that can be suggested) "Also suggested by similar quotes." (#63; the similar-quotes reason belongs to a quote and tag pair, so the sheet has no counts for it). Long-press starts multi-selection with a contextual bar for rename-one (tag rules applied while typing; "Merge #Luv into #Love (3 quotes)?" when the name exists) and delete-many ("Remove #X from N quotes?").

**Add/Edit hashtag field** — `HashtagChipField` in `AddEditActivity`: the quote's tags as input chips (alphabetical) followed by the text being typed, in a `ChipGroup`. Space, Enter, comma or a dropdown pick commits the text as a chip; disallowed characters are dropped while typing (the `Editable` is edited in place, not with `setText`, which would reset the keyboard and lose the next keystroke); a tag the quote already has is ignored. A chip's × removes it; Backspace in the empty field highlights the last chip, a second one removes it. The dropdown lists existing tags starting with the input, most-used first, at most 3, with counts (`SuggestionProvider.getTagSuggestions`), leaving out the quote's own; empty input or a lone `#` has none, so it never opens on focus or after a pick (#54). It always opens right under the field's line, over the Suggested row (`DropDownBelowTextView` caps its height to the space above the keyboard instead of flipping above the field), and focusing the field scrolls the form to put it at the top (with blank space below the form when it is too short to scroll that far). Save commits leftover text first; `QuoteFormSnapshot` compares the normalized tag list. Under the field sits the "Suggested" row (see Hashtag suggestions).

**Hashtag suggestions** — up to 3 tags proposed while adding or editing a quote (#50), learned on the device from the user's own collection; no network. Nothing is persisted except the Quote Embeddings cache (#62). `HashtagSuggester` (pure): `fit(quotes, vectors)` counts per tag which tokens its quotes contain; `suggest(text, author, source, existingTags)` looks for reasons; `existingTags` are the chips in the field, live. *Tokens*: quote text lowercased, split on non-letters, words under 3 letters and English/German stopwords dropped, the rest stemmed with Snowball (vendored in `org.tartarus.snowball`, BSD): German when the quote has more German than English stopwords, else English (`love`/`loved`/`loving` → `love`, `happy`/`happiness` → `happi`, `Liebe`/`lieben` → `lieb`; `friendship` stays apart from `friend`), plus one `author:<name>` and one `source:<name>` token (lowercased, spaces collapsed; none when empty) and a `tag:<key>` token per tag (in `fit` the quote's tags, in `suggest` the chips); a quote counts each token once. *Reasons* (#52): a word of the quote is a reason for a tag when ≥ 3 quotes contain it and have the tag, and that is ≥ 40% of the quotes containing it (so "time (1/66)" is not); the author is a reason when ≥ 2 of their quotes have the tag, and that is ≥ 40% of their quotes; the source likewise (≥ 2 of its quotes, ≥ 40%); a tag of the quote is a reason when ≥ 4 quotes have it and the tag, and that is ≥ 40% of the quotes with it (a tag is never a reason for itself); a word whose stem is a stem of the tag's name (English or German Snowball, so `lieben` for #Liebe) is a reason regardless of counts, but ranks below every counted reason (`Evidence.nameMatch`). So a chip added from a suggestion can bring up the next one. *Similar quotes* (#61, ADR-006): with quote vectors (`fit(quotes, vectors)`, quote id → normalized vector from the Embedder; `suggest(..., vector)` / `explain(..., vector)` for the text being judged), the quote's neighbours are the 10 tagged quotes most similar to it (cosine ≥ 0.40, tuned for paraphrase-multilingual-MiniLM-L12-v2; untagged quotes are never neighbours, the quote is never its own); a tag on ≥ 3 of them has the reason "3 of 10 similar quotes" (`Evidence.similar`), ranked by share and count like every counted reason; `Explanation.similar` and `similarQuoteIds` (most similar first) carry it; every app surface (the editor's row, the ranked "No hashtag" / "Has suggestions" / "Suggested for" lists, the tagging run, the Hashtags screen's count, the hashtag sheet) passes the Quote Embeddings' vectors (#62); quotes without a vector yet have no such reason, so with an empty cache suggestions are exactly as before (the package-private `fit(quotes)` without vectors is for tests and the eval). The Why line adds "similar to 4 of the 10 closest tagged quotes" after the quote's tags and before the name match. In both the Why dialog and the chip long-press dialog that part is a link (#63, `HashtagSuggestionRow.WhyMessage`, a `ClickableSpan`): a tap lists the neighbours with the tag under the line, most similar first, each as "• " plus its first 60 characters on one line, cut at a word break with "…" (`HashtagSuggestionText.neighbourLines`/`snippet`); another tap hides them; TalkBack announces the change. Neighbour ids are looked up in the Quote Collection when the dialog opens; a deleted one is skipped. The intro ends "Tap "similar to …" to see those quotes." *Eligibility*: the tag is on ≥ 5 quotes and the quote has ≥ 1 reason for it. Ranked by each tag's strongest reason (higher share, then higher count; compared in integers), ties by name; tags the quote already has and its rejected tags (ignoring case) never appear; rejections change no count. *Pinned* (#56): in a "Suggested for" tagging run the row shows the run's tag first whenever it is eligible (`suggest(..., pinned)`), then the best 2 others, still at most 3; rejecting it lets the row refill, adding it ends the pin. The constants live in code. `HashtagSuggestionRow` shows them under the chip field, hidden when none qualify: the "Suggested" label with an ⓘ button on top, the chips (outlined assist chips with a +) in a full-width wrapping row below; a tap adds the tag as a chip. *Rejecting* (#55): a long-press on a chip opens a dialog for that suggestion (its explanation line, then "Don't suggest for this quote" / Cancel); the tag joins the form's rejected tags (held by `HashtagSuggestionRow`) at once, so the next-best tag can appear, and is saved with the quote (`QuoteCollection.edit` with rejected tags; Add saves them too); discarding drops it, and `QuoteFormSnapshot` compares them (minus the form's tags). Rejections are only made by hand, never inferred from a save; adding the tag by hand drops it. *Why* (#51, #52): the ⓘ opens one dialog: how suggesting works (`HashtagSuggestionText.INTRO`), then a line per suggestion from `explain(text, author, source, tags, tag)`: the reason words strongest first as written in the quote, then the author and the source when they are a reason, then the quote's tags that are a reason, strongest first, then "contains the tag's name" when it does ("gratitude (6/9 quotes), grateful (4/7) · by Rumi (4/5) · from Masnavi (3/4) · with #Death (6/9)": 6 of the 9 quotes containing the word have the tag; only the first count names the unit), then "Not suggested for this quote: #Hope, #Love" when the form has rejected tags (out of reach when every suggestion is rejected and the row is hidden). Counts, never a percentage. `profile(tag)` gives every reason the model knows for a tag: its quote count, whether it can be suggested (≥ 5 quotes), all its reason words (a stem shown as the collection's most frequent full word), authors, sources and other tags, strongest first. The model is refitted on a background thread whenever the Quote Collection emits (so on opening, and after each Add), **without the quote being edited**, so its own words can't push back a tag the user just removed; the row refreshes 300 ms after the text, author or source last changed and at once when the chips change. The typed quote text is embedded on the row's own thread at each refresh (the cached vector when the text is a saved quote's), and the row refreshes again when its vector arrives; until then the previous text's vector is used. The model and the ranked lists refit when the Quote Embeddings emit.

**Ranked "No hashtag" and "Has suggestions" lists** — with the "No hashtag" filter (#53) or the "Has suggestions" filter (#55; every quote, tagged or not, with at least one suggestion; with or without text either way), `SearchFragment` ranks the results by `SuggestionRanking` (pure) instead of newest first: by the strength of each quote's top suggestion (higher share, then higher count), ties by the 2nd, then the 3rd suggestion, quotes without suggestions last (the "Has suggestions" list drops them), then newest first. The suggestions come from `HashtagSuggester.suggestionsFor` on a model fitted on the whole collection off the main thread whenever the collection emits, each quote's suggestions computed once per fit (the ranked results wait for it); it counts each of the quote's tokens (its tags' tokens included) one lower, as if it were left out, and leaves out its tags and rejected tags, so they are exactly the editor's (only the quote's own tags count it among their quotes, and those are never suggested for it). Same rules as the editor, no extra threshold. Each row adds a line "Suggested: #Gratitude (10/11) #Love (6/8)" (`HashtagSuggestionText.suggestedLine`: each tag with its strongest reason's counts, never a percentage, or "(name)" when that is the tag's name in the quote, or "#Grief (4/10, based on similar quotes)" when it is similar quotes, so the count doesn't read as a word count, #63), hidden when there are none. The **"Suggested for" list** of one tag (#56, `QuoteQuery.suggestedFor(tag)`, opened from the hashtag sheet) has every quote that tag is eligible for, whether or not stronger tags push it out of the quote's top 3 (`HashtagSuggester.suggestionFor(quote, tag)`, leave-one-out like `suggestionsFor`; null for the quote's own and rejected tags), ranked by that tag's strongest reason, then newest first; each row's line is the tag's explanation, "#Stoicism: virtue (4/6 quotes) · by Seneca (3/4)" (`explainFor`, counted as if the quote were left out; `HashtagSuggestionText.suggestedForLine`).

**Tagging run** — the editor opened from a ranked list (the quote dialog's edit, which then closes; `AddEditActivity.taggingRunIntent`, state in `TaggingRun`). From "Has suggestions" (#55) every save is done with the quote: it joins the run's skipped set whatever the save changed; the first save asks once "Continue with the next quote?", the Skip title reads "Skip to next quote", and the run ends with "No more suggestions"; otherwise as below. From one tag's "Suggested for" list (#56) a save is done with the quote when it adds or rejects the tag (`TaggingRun.isDecided`); the first such save asks once "Continue with the next quote for #Stoicism?"; a save that decides neither returns to the list before Continue and counts as Skip after it; "Skip to next quote", "No more suggestions for #Stoicism"; the editor pins the tag in the Suggested row. From "No hashtag": Saving a quote that had no hashtags when loaded and now has some asks once per run "Continue with next untagged quote?" (Continue / Back to list); after Continue each such save loads the next quote in place, with a toast. Next is the best-ranked quote still matching the list's query that is not skipped, from a model refitted after the save. Skip (toolbar, only in a run; discard check first) leaves the quote out for the rest of the run (memory only) and counts as Continue; Delete (after its confirmation) moves on the same way; a save that leaves the quote untagged skips it once continued. The title reads "Edit quote · N left" (the quotes still in the ranked list and not skipped, counted with a model fitted off the main thread). The run ends with Back/close or "No more untagged quotes", back on the list, which has re-ranked.

**Hashtag suggestion eval** — a local, repeatable measure of the Hashtag suggestions on the user's real collection (#59), the judge for model changes. `HashtagSuggestionEval` (pure, `app/src/test`) takes the quotes and a pluggable suggester `(quote) -> tags` and counts, over tagged quotes only (an untagged quote has no ground truth): *precision@3* (suggested tags the quote has / all suggested), *recall@3* eligible (only tags on at least `MIN_QUOTES_PER_TAG` quotes once the quote is left out) and unrestricted, *coverage* (quotes with a suggestion, tagged and untagged separately), and precision/recall per tag. `leaveOneOut(quotes)` is the current model exactly as the editor runs it on a new quote: refitted without the quote, no chips, its rejected tags left out. `HashtagSuggestionEvalReport` reads a Backup Document exported from the phone at `app/src/test/resources/private/backup.json` (gitignored; override with the `HASHTAG_EVAL_BACKUP` environment variable, or the `hashtagEval.backup` system property when run from the IDE), prints the report and writes `app/build/reports/hashtag-eval.txt`; without the file it is skipped (`Assume`), so CI stays green. The backup and the report never go into the repo. `similarQuotesBakeOff` (#61) adds the similar-quotes reason: `HashtagSuggestionEval.sweep` fits once per left-out quote and scores every `HashtagSuggester.Knn` parameter set (k, m, floor, ranked below counted reasons or not) off that fit, against the success bar (`passes`); it prints per model the decided k/m by floor, the whole sweep, per-tag changes and a chunked-vs-cut-off comparison to `app/build/reports/hashtag-eval-knn.txt`, and writes 20 random added suggestions with their nearest neighbours to `app/build/reports/hashtag-spotcheck-<model>.txt` for a manual check (quote text, never commit). `embedding.QuoteVectors` embeds the quotes once and caches the vectors in `app/build/embedding-cache/<model id>.tsv` keyed by text SHA-256 (optionally chunked: sentence-packed pieces, token-weighted mean).

**Reading Session** — a shuffled traversal of the Quote Collection. Tracks deck order, current position, and the currently displayed quote. Subscribes to the Quote Collection via `observeForever` and reconciles its deck reactively: new quotes append to the end, deleted quotes are removed with position adjusted, updated quotes are replaced in place. Implemented as an Android `ViewModel` scoped to `MainActivity`. Other flows (Favorites, Search results) maintain their own ordered views and do not use a Reading Session.

**Deck** — the ordered list of quotes inside a Reading Session, in the order they will be presented to the user. Initially a shuffle of the full collection; mutated in place as the collection changes.

**Reading position** — the zero-based index of the currently displayed quote within the Deck.

## Flows

**Main screen** — `MainActivity` is a bottom-navigation host: one app bar (title follows the tab; the Settings gear only on Quotes), three tab fragments — `QuotesFragment`, `SearchFragment`, `FavoritesFragment` — added once and switched with show/hide so each keeps its state, and the add-quote FAB (Quotes only). Back from Search or Favorites returns to Quotes; from Quotes it exits. An author/source tap on a card opens the Search tab with that single-field query, a hashtag tap with that tag's filter and an empty field (`QuoteQuery.forTag`); a notification tap or `EXTRA_QUOTE_ID` via `onNewIntent` opens the Quotes tab at that quote. Settings, Statistics, Hashtags and Add/Edit are pushed Activities without the bottom bar.

**Main browse flow** — the Quotes tab: ViewPager2 in `QuotesFragment` driven by the Reading Session's Deck (the session is scoped to MainActivity). There is no position counter (the deck is a shuffle; the total lives in Settings → Statistics); instead both quote pagers (Quotes and Favorites) show the edges of the neighbour cards, scaled down and faded (`PagerPeek`). Both pagers loop (`LoopingPositions`: the list repeats, starting in the middle lap), so the first card has a neighbour on its left too; positions stay deck/list indices everywhere except inside `QuotePagerAdapter`. A card swiped away scrolls back to its top once the pager settles. On each fresh app start the Quotes tab plays a swipe nudge (`SwipeHint`: the card fake-drags ~15% toward the next one and springs back) until the user has swiped once by hand (`UiPrefs/has_swiped`; programmatic jumps from a notification don't count). No nudge when opened from a notification, with fewer than 2 quotes, or with animations turned off.

**Favorites flow** — the Favorites tab: ViewPager2 in `FavoritesFragment` driven by a filtered, recency-sorted view of the Quote Collection (not a Reading Session). Observes the Collection, so ♥ taps elsewhere show up at once; keeps the shown quote in view across changes; shows an empty state when there are no favorites.

**Search / hashtag flow** — the result list in `SearchFragment` (the Search tab, or the thin pushed `SearchActivity` that Statistics and Hashtags open via `QuoteQuery.toIntent`) driven by a filtered view of the Quote Collection. A result tap opens the **quote dialog** (`QuoteDialogFragment`, a child of `SearchFragment`): the quote card (`view_quote_card`, bound by `QuoteCard` like the pager pages) centred over the dimmed screen, pager-card wide, a long quote scrolling inside it, a small round X above its top-end corner; X, Back or a tap outside closes it. The card is live (♥, share, edit; follows the Collection, closes when the quote is deleted); an author/source/hashtag tap closes it and runs that query in the search behind it. The card's tag line (`text_hashtags`) is one TextView showing `#A #B #C` (alphabetical, single spaces, wrapping), one `ClickableSpan` per tag, hidden when the quote has none. It is not a view: `timesShown`/`lastShown` stay untouched. Search results are newest first, except in the ranked "No hashtag" list (below) (`Quote.NEWEST_FIRST`: `addedAt` descending, then id descending — ids grow with each add, so quotes with unknown `addedAt` still order sensibly). Below the 3-character minimum the Search screen lists every quote ("N quotes"), so it doubles as the full, recently-added-first list.

**Quote Query** — immutable search predicate: trimmed text, the set of fields in scope (quote text, author, source, hashtags) and an optional **hashtag filter** (#51, ADR-005; replaced ADR-004's `exact` flag). Owns matching, the 3-character minimum, and result snippets. Text matches by case-insensitive contains; on hashtags, on each tag, ignoring a leading `#` in the query. The hashtag filter is off, one tag (whole tag, ignoring case), "no hashtag", "has suggestions" (#55) or "suggested for" one tag (#56) (`forTag(tag)`, `untagged()`, `suggested()`, `suggestedFor(tag)`: empty text with the filter; `withTag`, `withUntagged`, `withSuggested`, `withSuggestedFor`, `withoutTagFilter`; `withText` and `scopedTo` keep it). "Has suggestions" needs the suggestion model, so the query lets every quote through and `SuggestionRanking` keeps those with suggestions (`isRankedBySuggestions` covers it and "no hashtag"). A quote matches when it passes the filter and, with text of at least 3 characters, the text matches; the filter alone is enough to be active (no minimum, so `#AI` works). `SearchFragment` shows the filter as an input chip under the field (× removes it, a tap changes it); the filter dialog's "Hashtag…" button picks "No hashtag", "Has suggestions" (with its count once the model is fitted) or a tag, each with its count. A text match on a tag (and not in the quote text) shows the quote's tag line as the result snippet (`snippet(Quote)`); with only the filter, the snippet is the start of the quote. The search filter scopes it to all four fields or exactly one (`scopedTo`, `singleField`): the filter icon in the search field opens a single-choice dialog (All fields, Quote, Author, Source, Hashtags), the field label names the choice, and for author/source/hashtags the field suggests existing values (`SuggestionProvider.getFieldSuggestions`: any word starting with the input — for hashtags, tags starting with it — most-used first, at most 6, with counts). A single-field query is also what author/source click-through and Statistics produce. `toIntent`/`fromIntent` are the only protocol for opening SearchActivity for a query; `toBundle`/`fromBundle` carry it (the filter as `search_tag`, `""` for no hashtag, or `search_suggested`) as `SearchFragment` arguments and saved state. `SearchFragment` holds one as its state; picking a filter produces a new query, `applyQuery` replaces it.

## Subsystems

**Quote Statistics** — `QuoteStatistics.of(quotes)` (pure; clock and zone injectable) is the one place the Statistics screen's numbers are computed: totals, favorites, top-10 authors/sources, a Hashtags histogram (every tag, a quote counted once per tag; a row tap opens the search with that tag's filter), the without-hashtags count, quotes added per calendar month over the last 12 months (current month last; drawn by `MonthlyBarChartView`) and the count with unknown `addedAt`. Ties rank by count then name. `StatisticsActivity` only binds the result to views and three long-lived `StatItemAdapter`s.

**Quote text rendering** — `QuoteTextRenderer` (pure) is the one place a Quote becomes text: the share format and the daily-notification title/body (with the 150/300 truncation limits). Neither includes hashtags. `QuoteSharer` starts the chooser for both pager screens.

**Quote Notifications** — the daily-quote notification feature. A single facade (`com.example.myquotes.notifications.QuoteNotifications`) owns the WorkManager scheduling, the notification channel, the boot-reschedule BroadcastReceiver, the runtime `POST_NOTIFICATIONS` permission flow, the battery-optimization dialog, and the enabled/disabled flag. The rest of the app interacts only with this facade. See ADR-002.

**Quote of the day selection** — `notifications.QuoteOfTheDayPicker` (pure; clock and `Random` injected) picks the daily-notification quote (#37). *New pool*: `addedAt > 0`, never notified, and at least 24 h old — exempt from the cooldown. *Regular pool*: every other quote whose last notification and last in-app view (`lastShown`) are both at least 30 days ago; new quotes still inside their 24 h grace are in neither pool. A non-empty new pool is drawn from with probability 0.25, otherwise the regular pool, uniformly; an empty chosen pool falls through to the other; both empty → the quote least recently notified or viewed. The constants live in code, not settings.

**Notification history** — per-quote `notifiedCount`, `clickedCount`, `lastNotifiedAt` (`notifications.NotificationHistory`, keyed by quote id), stored by the `QuoteNotifications` facade in `QuoteNotificationPrefs/notification_history_json` — deliberately not on `Quote`, so `DailyQuoteWorker` can write it without racing the Quote Collection's saves. Written only by the worker (after a notification is actually posted; also prunes deleted ids) and by `QuoteNotifications.recordOpenedFromNotification` (called from `MainActivity`; counts only intents carrying the worker's `EXTRA_FROM_NOTIFICATION` marker, not on recreation or relaunch from Recents). An entry older than its quote's `addedAt` belonged to an earlier quote with a reused id and is ignored. Record-only for now: nothing displays it or feeds clicks into selection.

**Backup Document** — the file format for backups and manual export/import (`BackupDocument`): `{version: 3, quotes: [...], notificationHistory: {...}}`, built on `QuoteCodec`'s quote array, where each quote has `"tags": [...]` and no `"category"`, plus an optional `"rejectedTags": [...]` (#55; written only when non-empty, no version bump: older builds ignore it). Decoding also accepts v2 and v1 envelopes and bare arrays (empty history when there is none); a quote without `"tags"` gets its old `"category"` as one tag (`Hashtag.fromCategory`). Import replaces both the quote list and the notification history (a file without history clears it). The Quote Store keeps its own plain `QuoteCodec` envelope (version 2 since #49, same quote shape). An older build reading a v3 file or store loses the tags; that downgrade path is deliberately dropped (ADR-004).

**Backup Destination** — where a backup run puts its files. An interface (`backup.BackupDestination`) with five operations: check availability, write bytes under a filename, list existing entries (name plus opaque handle), read an entry's bytes back, delete an entry. Two adapters: `SafDestination` (a user-chosen local folder via the Storage Access Framework) and `DriveDestination` (the app-owned "MyQuotes Backups" folder under My Drive, via `DriveRestClient`; auth and network happen lazily in `checkAvailable`).

**Backup run** — one backup of a Backup Document (quotes plus notification history) to one Backup Destination (`backup.BackupRun`, no Android state). Encodes pretty-printed (matching manual export), hashes the exact bytes to be written, skips if that matches the destination's own most recent backup (read back and re-hashed, not a locally cached value — so a stale local cache can't cause a duplicate write), otherwise writes a `BackupFilename`-named file and prunes via `BackupRetention` to 9 files (7 daily + 1 weekly + 1 monthly). Returns an outcome (skipped-unchanged, written-with-hash, failed-with-cause); recording state and notifying is the caller's job.

**Auto-backup** — daily background backup to each enabled Backup Destination (local folder, Google Drive). One shared module in `backup`: `Backups.runOnce` (one Backup run of the Quote Store to a target's destination; a written backup records `BackupState` and clears the failure notification), `BackupWorker` (selects the target from input data, ends its chain when the target is off, runs `Backups.runOnce`, posts `BackupNotifications` on failure, always re-arms and returns success), `BackupScheduler` (a `scheduling.WorkChain` per destination, 24 h apart; Drive requires any network), and `BackupTarget` (per-destination constants: prefs file `LocalBackupPrefs`/`DriveBackupPrefs`, channel id, notification ids 1002/1003). Settings' **Back up now** row (under the two switches) runs `Backups.runOnce` for every target that is on, one after the other off the main thread, and toasts a line per target ("Backed up to your local folder", "Nothing changed since the last backup to Google Drive", "Backup to … failed: …") instead of notifying; disabled with "Turn on an auto-backup above first" when neither is on. `LocalBackup` and `DriveBackup` are thin facades for the enabled flag / SAF folder permission / `DriveBackup.connect(email)` + `disconnect()`. See ADR-003.

**Google Drive auth** — auth plumbing for Drive-based backup. A single facade (`com.example.myquotes.drive.DriveAuth`) owns the enabled/connected-account SharedPreferences and a two-step connect flow: Credential Manager (`androidx.credentials`, Google ID token option) shows the account chooser and returns the signed-in account's email, then the Authorization API (`com.google.android.gms.auth.api.identity`) requests the `drive.file` scope, surfacing a consent `PendingIntent` when needed. `SettingsActivity` owns the `ActivityResultLauncher<IntentSenderRequest>` that launches that consent UI and feeds the result back into `DriveAuth.completeAuthorizationResult`. Disconnecting clears the stored account and calls `CredentialManager.clearCredentialStateAsync` to drop the cached credential state. The OAuth client ID (from #14) is wired in as `BuildConfig.DRIVE_OAUTH_CLIENT_ID` via `local.properties`. `DriveAuth.getAccessToken` re-runs the Authorization API silently (no UI) to mint a fresh token for background use; it throws if the grant needs to be re-resolved interactively (e.g. revoked).

**README screenshots** — `./gradlew readmeScreenshots` (task in `app/build.gradle`, not part of CI) captures the images in `docs/screenshots/` on the one running emulator (or `ANDROID_SERIAL`); real devices are never selected. It installs the debug and test APKs, turns on system UI demo mode (12:00, full battery, full Wi-Fi, no notification icons; always exited afterwards), runs the androidTest `ReadmeScreenshots` via `am instrument` (fails on `FAILURES!!!` or no `OK (`), and replaces the PNGs in `docs/screenshots/` with the pulled ones. The test is gated by `EmulatorOnlyRule` (outermost rule): skipped without the `readmeScreenshots=true` argument, failed before touching anything on a non-emulator. It loads the **demo collection** (`androidTest/assets/demo_quotes.json`, a v3 Backup Document: 32 sourced quotes by public-domain English-language authors, 12 hashtags with 1–3 per quote and 3 quotes untagged, 6 favorites, `addedAt` spread over ~11 months), shifts all timestamps so the newest is 2 days old, replaces the Quote Collection (and so the Hashtag set), marks the deck swiped, and whitelists the app from battery optimizations. A stable deck comes from a seeded `Random` set through `MyApplication.setShuffleRandom` (production: unseeded) plus `EXTRA_QUOTE_ID` at a fixed headline quote. Screens, each in its own `ActivityScenario` (closed even on failure): `quotes`, `favorites` (tab via the bottom nav), `search` (author query "Jane Austen" set through `MainActivity.showSearch`, so the field has no focus, keyboard or suggestion popup), `quote-dialog` (4th result tapped), `statistics` (asserts ≥ 10 of the 12 chart months have quotes), `hashtags`, `settings` (fails if `DriveAuth.getConnectedAccountEmail` is set, so no account email reaches a README image). Every screen is taken twice: light (theme forced to `MODE_NIGHT_NO`) and dark (`MODE_NIGHT_YES`, `<name>-dark.png`), set through `MyApplication.setThemeMode`; the same seeded deck makes each pair show the same content. The theme setting found before the run is put back in `@After`, also when a capture fails (`setThemeMode` commits synchronously so that last write survives the instrumentation process ending). `ReadmeScreenshotCapture` writes `<name>.png` to the app's external files dir under `readme-screenshots/`.

**Embedder** — turns a quote's text into a vector for semantic search (#58, #60): `embedding.Embedder` (`embed(text)`, `modelId()`, `dimensions()`), L2-normalized so cosine = dot product. Pure Java callers depend only on the interface. `OnnxEmbedder` runs a `TextEmbeddingModel` with ONNX Runtime (`onnxruntime-android` in the app, the desktop `onnxruntime` jar of the same version in unit tests): the model's prefix plus the text, cut off at 128 tokens (special tokens included, never rejected), `input_ids` + `attention_mask` (+ `token_type_ids` when the graph has it), mean pooling over the mask, then normalize. One `OrtSession`, created on first use, closed with `close()`. `TextEmbeddingModel` lists the two bake-off candidates, both int8-quantized Xenova ONNX exports with 384 dimensions: `MULTILINGUAL_E5_SMALL` (prefix `"query: "`) and `PARAPHRASE_MULTILINGUAL_MINILM_L12` (no prefix). `id()` is the name plus the pinned revision, e.g. `multilingual-e5-small@761b726d`, so a model change invalidates stored vectors. `OnnxEmbedder` takes the model from a file (tests) or a direct `ByteBuffer`. In the app, `AssetEmbedder` maps `assets/embedding/model_quantized.onnx` straight from the APK (stored uncompressed, `noCompress 'onnx'`) and reads `assets/embedding/tokenizer.json`, both on the first `embed` and kept for the process (about 290 MB PSS while loaded, measured on the emulator; no idle release); `modelId()` needs neither. Only paraphrase-multilingual-MiniLM-L12-v2 (ADR-006) is packaged.

**Quote Embeddings** — a vector per quote for the similar-quotes reason (#62): `QuoteEmbeddings`, owned by `MyApplication` like Hashtags. A cache that can always be rebuilt, never in the Quote Store or the Backup Document: text hash (first 8 bytes of SHA-256) → vector, saved in `filesDir/quote-embeddings.bin` (`QuoteEmbeddingsFile`: header, model ID, vectors; written to a temp file and moved; an unreadable file is no cache) together with `Embedder.modelId()`; a different model ID throws the cache away. It observes the Quote Collection: new or changed texts are embedded on one background-priority thread, texts no quote has any more are dropped (quotes with the same text share a vector), and a newer collection cuts an old pass short. Every 64 vectors and at the end of a pass it saves and emits `getChanges()`. `snapshot()` / `vectorsFor(quotes)` give an immutable quote id → vector map of the quotes that have one; `cached(text)` looks a text up; `embed(text)` (blocking, off the main thread) embeds the editor's text without caching it. When the embedder fails (no model in the APK), it logs once and embeds nothing more in that process.

**Embedding models download** — the model files are not committed (too big). `./gradlew downloadEmbeddingModels` (task in `app/build.gradle`, a dependency of every unit test task and of `embeddingAssets`, which copies the MiniLM files into the APK's generated assets; without them the APK builds with a warning and the app suggests without the reason) fetches each `model_quantized.onnx` and `tokenizer.json` from Hugging Face at a pinned commit, checks each against its SHA-256 (a mismatch fails the build) and caches them in `~/.gradle/caches/myquotes-embedding-models/<name>/<revision>/`. Tests find them through the system property `myquotes.embeddingModels`, and tests that need a model `Assume` it is there, so an offline run (the task only warns then, unless it was asked for by name) still passes the rest. The names and revisions must match `TextEmbeddingModel`. On Windows, ONNX Runtime needs `msvcp140.dll` 14.40+, but the JVM loads the copy in its own `bin` first and Android Studio's JBR ships 14.29, which crashes the test JVM. So the test task reads that DLL's version and skips the ONNX tests (`myquotes.onnxSkipReason`) unless `unitTest.javaHome` in `local.properties` points at a newer JDK to run the unit tests on. CI runs on Linux and downloads once into its Gradle cache.

**XLM-R tokenizer** — `embedding.UnigramTokenizer`, the SentencePiece unigram tokenizer both models use (250k vocabulary), in pure Java and read from `tokenizer.json`, with no native code. The pipeline: normalizers (`Precompiled`: `PrecompiledCharsMap`, the Darts trie of NFKC replacements, applied per grapheme cluster under 6 UTF-8 bytes and otherwise per code point, quirks included; `Replace`), pre-tokenizers (`WhitespaceSplit`, `Metaspace`), then per piece the Viterbi best split by vocabulary score, with unknown characters scored `minScore - 10` and a run of them fused into one `<unk>`, then `<s> … </s>`. The two models differ only in config: e5 collapses runs of spaces and keeps a lone `▁`, and MiniLM splits on whitespace first. `GraphemeClusters` is a small written-out subset of the UAX #29 rules, so results don't depend on the JDK's `BreakIterator`. Literal special tokens in the text (`<mask>`) are not matched as special tokens. `UnigramTokenizerGoldenTest` checks it against the official Hugging Face `tokenizers` on 51 sentences (fixture `embedding/tokenizer-golden.json`, written by the one-time `tools/generate_tokenizer_golden.py`).
