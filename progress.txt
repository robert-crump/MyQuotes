2026-09-19 — Issue #23: Backup Destination seam — one backup run for local and Drive

Collapsed the two copy-pasted backup subsystems into one module. New: `BackupDestination` (interface) with `SafDestination` / `drive.DriveDestination` adapters; `BackupRun` (no Android state: encode pretty, hash the written bytes, skip if unchanged, write timestamped file, prune via BackupRetention, return SKIPPED_UNCHANGED / WRITTEN(hash) / FAILED(cause)); `BackupTarget` (per-destination constants; pref file names, channel ids and notification ids 1002/1003 unchanged); `BackupState`, `BackupNotifications`, `BackupScheduler`, and a single `BackupWorker` that picks the destination from input data. `LocalBackup` and `DriveBackup` shrank to thin facades; `LocalBackupWorker`/`DriveBackupWorker` deleted. `DriveBackup.connect(email)` / `disconnect()` fold the DriveAuth flag and the schedule together, so `SettingsActivity` makes one call per transition (four hand-paired sites gone; `DriveAuth.markConnected/disconnect` are now package-private).

Defects closed: local and Drive now write identical pretty-printed bytes and the stored hash is over those bytes (first run after upgrade writes one extra backup because the old stored hash was of the compact string). Backups moved from PeriodicWorkRequest+UPDATE to the self-rescheduling one-shot chain via a new shared `scheduling.WorkChain`, which `QuoteNotifications` now uses too; old periodic jobs are cancelled on startup and the chains use new work names (`backup_local`, `backup_drive`), Drive keeps NetworkType.CONNECTED.

Found while doing this: the #21 fix re-armed from inside `doWork()` with `ExistingWorkPolicy.KEEP`, but the running request still counts as unfinished work under that name, so KEEP is a no-op there and the chain only healed on the next app open. `WorkChain.rearmFromWorker` uses `APPEND_OR_REPLACE` (worker must return success or the appended successor is cancelled), and `DailyQuoteWorker` uses it too. Reasoned from WorkManager's documented semantics, NOT verified on device. Behaviour change: a failed backup run now posts the notification, re-arms, and returns success instead of Result.failure().

Tests: new `BackupRunTest` (skip on unchanged hash, filename parses back to clock timestamp, recorded hash equals hash of received bytes, prune converges on 9 over 15 simulated days, write failure -> FAILED with no hash). Docs: CONTEXT.md (Backup Destination, Backup run, Auto-backup replace the two subsystem entries), ADR-003. Build and all unit tests pass. On-device verification deferred to the user. Issue #23 closed.
