2026-11-07 — Issue #67: Quote Embeddings: the only thread that runs the Embedder, editor text included

`QuoteEmbeddings.embedLatest(text, onMain)` replaces the blocking `embed(text)`. A cached text, an empty text or an unavailable embedder answers at once, inside the call. Otherwise the text waits in a single slot (`AtomicReference<Request>`) and is embedded on the cache's own worker thread. A newer request replaces a waiting one, which is never answered, so only the latest typed text is embedded. The pass serves a waiting request before each text it embeds, so the editor never waits for a whole pass. The answer posts to the main thread, never for a cancelled `Request`, and is not cached. `HashtagSuggestionRow` lost its `embedder` executor and `volatile embedding`. It keeps the text it asked for and its `Request`, cancels the old one when the text changes and in `release()`, and refreshes again only when the answer comes later (a synchronous cache answer is used by the running refresh). The Embedder now runs only on the Quote Embeddings' thread, so two ONNX inferences never run at once. CONTEXT.md updated (Quote Embeddings, Hashtag suggestions). `QuoteEmbeddingsTest`: the two `embed()` tests were replaced and 6 added (manual worker, a fake embedder with an after-embed hook): a cached or empty text answers at once without embedding; three quick requests embed only the last; a request made during a pass is served before the remaining texts (a1, typed, b22, c333); the editor's vector is not cached or saved; a cancelled request is neither embedded nor answered; a failing embedder answers null (both mid-session and when already unavailable).
