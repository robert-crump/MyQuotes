2026-09-22 — Drive backup: fixed duplicate uploads from stale local state

Root cause: `BackupRun` decided "unchanged, skip" by comparing against a hash cached locally in `BackupState` (SharedPreferences), written only after `destination.write()` returned. If the process died between the upload succeeding and that local write landing (or any other way the cache fell out of sync with reality), the next run trusted the stale cache and re-uploaded identical content — seen as two Drive files with the same minute-resolution filename.

Fix: `BackupRun` now compares against the destination's own most recent backup (read back and re-hashed) instead of any locally cached value, so it's self-healing regardless of why local state went stale. `BackupDestination` gained `read(Entry)`; `SafDestination` reads the local file, `DriveDestination`/`DriveRestClient` added a `GET .../files/{id}?alt=media` download. `BackupState` dropped the now-unused hash field — it only tracks last-backup time for the Settings display now. `BackupRun.run` dropped its `lastHash` parameter accordingly; `BackupWorker` and tests updated. `BackupRunTest` adds coverage for the crash-recovery case (no local cache, destination still has the same content → skip).

Build and all unit tests pass. On-device verification (watch for a repeat duplicate) deferred to the user.
